# Fork Divergence: `hathaway3/nitros9A` vs `nitros9project/nitros9`

A quick-reference map of how this fork differs from its upstream, `nitros9project/nitros9` (`main` branch). Generated by diffing `main` against `upstream/main` as of **2026-08-14**.

## TL;DR

- **54 commits ahead** of upstream (this fork's own work, June 7 – August 14, 2026).
- **102 commits behind** upstream (real upstream changes not yet pulled into this fork — see [What's not merged from upstream](#whats-not-merged-from-upstream)).
- **One large structural divergence**: this fork still carries the entire `3rdparty/` tree (~1,187 files, ~544,000 lines — packages, drivers, utils, custom boot loaders), which **upstream's `main` branch no longer has at all**. That's not from any of the 54 commits below; it predates this fork's own divergence point and upstream apparently dropped the directory afterward. If you ever want to slim this fork down toward upstream's current shape, that tree is the first thing to look at.
- Five files are protected from being silently overwritten by a future upstream merge (`git merge`'s `merge=ours` driver) — see [Merge protection](#merge-protection-your-local-fixes-are-safe-on-merge).

## How this was generated

```sh
git remote add upstream https://github.com/nitros9project/nitros9.git   # once
git fetch upstream
git log --oneline upstream/main..main      # commits unique to this fork
git log --oneline main..upstream/main      # commits unique to upstream (not yet pulled)
git diff --stat upstream/main..main        # full file-level diff (inflated by the 3rdparty/ gap above)
```

Re-run those after `git fetch upstream` any time you want a fresh picture — this file is a snapshot, not a live view.

## The fork's own commits, by area

### RPI-Nine emulator integration

The single biggest reason this fork exists: getting NitrOS-9 booting correctly on the [RPI-Nine](https://github.com/hathaway3/RPI-Nine) bare-metal 6809/6309 emulator (RP2350/Pico 2). All of this is `recipes/coco3/40d`-scoped.

| Commit | What |
|---|---|
| `4cf8bf46`, `8fa5572a` | Fixed missing assembler include paths (`-I$(LEVEL1)/$(PORT)`) that broke the `atari`, `corsham`, and `mc09` ports' own CI builds once CI actually started reaching them (see CI fixes below) — undefined-symbol errors in `attr.asm` (`DIR.SZ`/`FD.SEG`/`FD.OWN`) because each port's own `defsfile` was never on the search path. |
| `fef1e71e` | **The big one.** Three real kernel/driver bugs fixed so the *standard*, unmodified 80-column windowed console (`vtio.dr`/`cowin.io`/`GrfDrv`) boots to a working `Shell+` — previously this fork defaulted to a lean ACIA-console workaround (`ACIA=1`, below) because the real console crashed. Root causes: `krnp2.asm` never initialized `<D.Crash`; `sysgo.asm`'s `Crash:` handler used direct-page addressing unsafe from non-task-0 context; `SysGo`'s optional CoCo-BASIC-warmstart setup treated its own expected resource-exhaustion failure as fatal instead of skipping it. Also fixed `docs/OS9Boot order.md` #1 (bootfile module layer ordering) for the standard 40d build. |
| `a4ec6ee0`, `ed313275`, `a5c4dc32` | `F$NProc`/`CpUsrStkTo`/`CpSysStkTo` DAT-page-collision investigation — a wrong fix (`a5c4dc32`, reusing `D.Quick`) was tried, found to cause a worse regression, reverted (`ed313275`), and replaced with the real fix: stop aliasing the `P$SP` copy onto the same DAT page as kernel scratch memory. |
| `77cc3260`, `e96f0d86` | `GrfDrv`'s hand-rolled DAT image never seeded slot 7 with `KrnBlk` — task-switching into `GrfDrv` could silently lose the kernel/vector page. Seeded and protected in both `cowin.asm` and `F$AllPrc`/`F$Chain`. |
| `21762f42` | Added the `ACIA=1` recipe toggle — swaps `GrfDrv`/`CoWin` for an RS-232-Pak-style 6850 ACIA console matching RPI-Nine's *emulated* hardware. This was the fork's default boot path until `fef1e71e` made the real console work; still available as an opt-in fallback. |
| `34484c54`, `1b2445a4` | Recipe build-order/include bugs: `BOOTMODS` layer ordering under `MINIMAL=1`, and a duplicate `coco3.mak` include that broke `recipes/coco3/40d` outright. |

## Merge protection: your local fixes are safe on merge

`.gitattributes` marks five files `merge=ours` (commits `6f729069`, `e22f4280` — requires `git config merge.ours.driver true` to actually take effect locally):

```
level1/cmds/dir.asm
level1/cmds/mdir.asm
level1/cmds/ident.asm
level1/cmds/dump.asm
level2/cmds/mdir.asm
level2/modules/kernel/ccbkrn.asm
level2/modules/kernel/krn.asm
level2/modules/kernel/krnp2.asm
level2/modules/kernel/mc09krn.asm
level2/modules/kernel/fallprc.asm
```

If you `git merge upstream/main` in the future, these ten files will **keep this fork's local version unconditionally**, even if upstream also touched them. That's deliberate (they carry the performance work and boot-failure fixes above), but it also means upstream improvements to *these specific files* won't come through automatically — worth a manual look if you ever do merge upstream and care what changed there.
